## 2. 需求审查

- 对照案例要求逐项核查（见 Spec 第 5 章验收清单），全部落实
- 权限模型简化合理：4 角色（案例要求），审批流简化为主管单级审批（案例说明"审批流程简化，无需复杂工作流"）
- 请假天数按自然日计算为已知简化项，在文档中已注明口径

## 3. 架构审查

- 单一职责：路由层仅编排业务，数据访问统一走 ORM 会话（依赖注入 `get_db`）
- 无循环依赖：`dashboard` 路由复用 `attendance` 的统计函数，依赖方向单向
- 前端路由守卫 + 后端角色依赖双重鉴权，纵深防御

## 4. 数据库审查

| 检查点 | 结果 |
| --- | --- |
| 唯一性约束 | users.username、employees.employee_no、attendance(employee,date)、salaries(employee,year,month) 均设置 |
| 外键完整性 | 删除部门/职位/员工前检查下游引用，删除员工前检查账号关联 |
| 索引 | 高频查询路径（员工列表、月度统计）均有索引或数据量可承受全表扫描 |
| 数据口径 | 出勤率、请假天数口径统一集中在统计函数，避免散落重复逻辑 |

## 5. 安全审查

### 5.1 已落实
- 密码 PBKDF2 加盐哈希（10 万次迭代），数据库无明文
- JWT HS256 签名 + 12 小时过期
- 全部写接口按角色声明权限（`require_roles` 依赖）
- 主管审批校验部门归属（仅可审批本部门员工）
- SQLAlchemy 参数化查询，无 SQL 拼接
- Excel 导入逐行校验，异常捕获不中断整体流程

### 5.2 遗留风险与建议（课程演示范围可接受）
| 风险 | 建议 |
| --- | --- |
| 演示密钥硬编码在 config.py | 生产环境改为环境变量注入 |
| CORS 全放行 | 生产环境限制为前端域名白名单 |
| SQLite 单文件存储 | 生产环境迁移 PostgreSQL/MySQL |
| 登录无验证码/限流 | 生产环境补充防暴力破解策略 |
| 打卡时间由客户端提交 | 生产环境由服务端时间戳为准，防止手动改时间补卡 |

## 6. 审查问题整改记录

| 编号 | 问题 | 发现阶段 | 整改 |
| --- | --- | --- | --- |
| 1 | 员工路由中 `/export/excel` 可能被 `/{emp_id}` 路径参数吞掉 | 接口联调 | 调整路由定义顺序，固定路径前置 |
| 2 | Excel 导出文件名含中文导致 HTTP 头 latin-1 编码报错 | 接口联调 | 文件名改为 ASCII 格式 |
| 3 | 薪资趋势取数月份方向错误（range 负数不生效） | 接口联调 | 修正 `month_bounds` 负偏移处理逻辑 |
| 4 | 打卡接口返回结构包含 Pydantic 未定义字段导致序列化错误 | 接口联调 | 改为 `{message, record}` 明确结构 |
| 5 | 审批结果通知标题拼接重复（"请假申请已已通过"） | 端到端测试 | 修正通知文案为 `申请 + 状态` |
