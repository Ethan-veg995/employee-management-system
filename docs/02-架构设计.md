# 企业员工管理系统 — 技术架构设计

| 文档版本 | V2.0（扩展审批工作流/消息通知/绩效/公告） |
| --- | --- |
| 编写日期 | 2026-08-24 |

## 1. 总体架构

采用前后端分离的单体架构，浏览器通过 HTTP/JSON 与后端交互，数据存储使用 SQLite 文件数据库。

```
┌──────────────────────┐       HTTP/JSON (JWT)       ┌──────────────────────┐
│     浏览器 (Vue3)     │ ───────────────────────────▶ │  FastAPI 后端 (Python) │
│  Element Plus UI      │ ◀─────────────────────────── │  SQLAlchemy ORM        │
│  ECharts 图表         │                              │  9 张业务表            │
│  Pinia 状态管理       │                              │  SQLite 文件数据库     │
└──────────────────────┘                              └──────────────────────┘
        │ 开发模式：Vite 3000 端口
        │ /api/* 代理转发 → 8000 端口（规避跨域）
```

## 2. 技术选型

| 层 | 技术 | 选型理由 |
| --- | --- | --- |
| 前端框架 | Vue 3 + Vite | 课程主推栈；组合式 API 开发效率高 |
| UI 组件库 | Element Plus | 企业后台系统事实标准，中文文档完善 |
| 图表 | ECharts 5 | 数据可视化能力强，看板 6 类图表均可覆盖 |
| 状态管理 | Pinia | Vue3 官方推荐，轻量 |
| HTTP | Axios | 拦截器统一处理 Token 注入与错误提示 |
| 后端框架 | FastAPI | 课程主推栈；Pydantic 自动校验请求参数；自带 Swagger 文档 |
| ORM | SQLAlchemy 2.0 | 参数化查询防 SQL 注入；模型与数据库解耦 |
| 数据库 | SQLite | 零配置文件型数据库，满足百人级企业规模，便于课程演示与云端沙箱部署 |
| 认证 | PyJWT + HTTP Bearer | JWT 无状态鉴权，前端 localStorage 保存 |
| 密码存储 | PBKDF2-HMAC-SHA256 | 标准库实现，加盐 10 万次迭代，无第三方依赖 |
| Excel | openpyxl | 员工导入导出 |

## 3. 后端分层设计

```
backend/app/
├── main.py         # 应用入口：注册 CORS、路由、建表
├── config.py       # 配置常量（密钥、角色、额度阈值）
├── database.py     # 数据库引擎与会话
├── models.py       # ORM 模型（9 张表）
├── schemas.py      # Pydantic 请求/响应模型
├── auth.py         # 密码哈希、JWT、角色鉴权依赖
├── seed.py         # 演示数据初始化
└── routers/        # 按业务模块划分的 10 个路由
```

设计原则：
- **分层解耦**：路由层只做参数校验与业务编排，数据访问统一走 ORM
- **鉴权统一**：`require_roles()` 依赖注入实现接口级角色控制，路由声明即权限声明
- **Pydantic 双重校验**：入参校验 + 出参序列化，保证接口契约稳定

## 4. 前端架构

```
frontend/src/
├── main.js         # 入口：注册 Pinia/Router/ElementPlus/图标
├── router/         # 路由 + 登录守卫 + 角色守卫
├── store/user.js   # 用户状态（Token、角色）
├── utils/request.js # axios 封装（Token 注入、401 自动登出、错误提示）
├── utils/chart.js  # ECharts 渲染与销毁封装
├── api/index.js    # 全部接口调用统一出口
├── layout/         # 侧边栏布局（按角色动态渲染菜单）
└── views/          # 16 个页面组件
```

关键机制：
- **路由守卫**：未登录跳转登录页；访问无权限路由时重定向到角色默认页
- **菜单动态化**：`MainLayout` 按当前角色过滤菜单项
- **代理转发**：开发环境 Vite proxy 将 `/api/*` 转发到后端 8000 端口，规避跨域；`request.js` 基址默认使用相对路径 `/api/v1`，可被环境变量覆盖，兼顾本地与 CloudStudio 两种部署形态

## 5. 关键业务设计

### 5.1 考勤状态判定（打卡时实时计算）
```
打卡时读取考勤规则（单行表）：
 迟到 = 上班打卡 > 上班时间 + 容忍分钟
 早退 = 下班打卡 < 下班时间
 缺卡 = 有上班卡无下班卡
 正常 = 其余
```

### 5.2 出勤率计算（月度统计）
```
应出勤天数 = 当月周一~周五天数
出勤率 = 实际出勤天数 ÷ (应出勤天数 - 已通过请假天数)
```
（简化口径：不考虑法定节假日，文档注明口径即可）

### 5.3 通用审批工作流（V2 扩展）
统一 `approval_requests` 表承载请假/加班/报销/出差四类申请，`request_type` 字段区分类型：
- 新增审批类型只需扩展前端表单，后端表结构与审批逻辑零改动 → 可迭代拓展
- 提交时自动查找审批人（本部门 manager 账号，兜底 hr），生成"待办"通知
- 审批通过/驳回后自动生成"结果"通知给申请人（消息闭环）
- 经理审批校验部门归属，防止跨部门越权

### 5.4 消息通知（V2 扩展）
- 轻量方案：前端 30 秒轮询 `/notifications/unread-count`，顶栏铃铛展示未读数与最近 10 条
- 与 WebSocket/SSE 对比：零额外依赖、部署简单、企业百人规模完全够用（文档说明可平滑升级 SSE）
- 通知类型：todo（待办）/ result（审批结果）/ announcement（公告）

### 5.5 绩效-薪资联动（V2 扩展）
```
评分 → 等级（S≥90 / A≥80 / B≥70 / C<70）→ 系数（1.5/1.2/1.0/0.6）
建议绩效奖金 = 系数 × 基本工资 × 20%（薪资录入时自动带出，可修改）
```
规则集中在 config.py（PERF_LEVELS / PERF_COEFF / PERF_BONUS_RATE），调整无需改代码。

### 5.6 智能提醒（规则引擎）
配置驱动：连续迟到阈值（3 天）、缺卡阈值（3 次）、请假额度（年假 5 天/事假 10 天）、部门出勤率阈值（90%）。规则集中在 `config.py`，可在不改代码的情况下调整。

## 6. 部署架构

- **本地开发**：后端 `uvicorn`（8000）+ 前端 `vite dev`（3000）
- **CloudStudio 沙箱**：`start.sh` 一键安装依赖并拉起前后端；Vite 监听 0.0.0.0，平台自动识别 3000 端口生成公网预览链接；只暴露前端端口，`/api` 由 Vite 代理转发，无跨域问题
- 数据库为沙箱内 SQLite 文件，随环境生命周期存储

## 7. 安全设计

| 风险 | 对策 |
| --- | --- |
| SQL 注入 | SQLAlchemy 参数化查询，无字符串拼接 SQL |
| 密码泄露 | PBKDF2 加盐哈希（10 万次迭代），库中不存明文 |
| 越权访问 | 每个接口按角色声明权限；经理审批校验"仅本部门" |
| Token 伪造 | JWT HS256 签名 + 12 小时过期 |
| 跨域 | 开发期 CORS 全放行（内网演示）；生产建议收紧为白名单 |
